**1. 前端优化层**
- 静态资源CDN加速,减少服务器压力
- 页面按钮倒计时,防止提前点击
- 前端限流,同一用户短时间内只能点击一次

**2. 接入层**
- Nginx负载均衡,分发请求
- 动静分离,静态资源不走后端

**3. 网关限流层**
- 令牌桶/漏桶算法限流
- IP黑名单,防止恶意刷接口
- 验证签名token,防止重放攻击

**4. Redis预减库存**
- 秒杀开始前将库存加载到Redis
- 使用Lua脚本原子性扣减库存
- 扣减成功才允许进入后续流程

**5. 消息队列削峰**
- 请求通过Redis校验后投入MQ
- 异步消费消息创建订单
- 保护数据库不被击垮

**6. 订单异步处理**
- 从MQ消费消息
- 扣减数据库库存
- 创建订单记录
- 返回结果通知用户

## 27. Redis预减库存实现

### 核心思路
使用Redis的原子操作和Lua脚本来保证库存扣减的准确性和高性能。

### 具体实现

```java
// 1. 秒杀开始前预热库存到Redis
public void initStock(Long productId, Integer stock) {
    String key = "seckill:stock:" + productId;
    redisTemplate.opsForValue().set(key, stock);
}

// 2. Lua脚本实现原子扣减
String luaScript = 
    "local stock = redis.call('get', KEYS[1]) " +
    "if not stock or tonumber(stock) <= 0 then " +
    "    return -1 " +  // 库存不足
    "end " +
    "local userId = ARGV[1] " +
    "local limitKey = 'seckill:limit:' .. KEYS[1] .. ':' .. userId " +
    "if redis.call('exists', limitKey) == 1 then " +
    "    return -2 " +  // 已经购买过
    "end " +
    "redis.call('decr', KEYS[1]) " +
    "redis.call('setex', limitKey, 86400, 1) " +  // 限购24小时
    "return 1";  // 扣减成功

// 3. 执行Lua脚本
public Long decrStock(Long productId, Long userId) {
    String stockKey = "seckill:stock:" + productId;
    
    DefaultRedisScript<Long> script = new DefaultRedisScript<>();
    script.setScriptText(luaScript);
    script.setResultType(Long.class);
    
    Long result = redisTemplate.execute(
        script, 
        Collections.singletonList(stockKey),
        userId.toString()
    );
    
    return result;
}
```

### 保证准确性的措施

**1. Lua脚本原子性**
- Redis单线程执行Lua脚本
- 避免并发问题导致超卖

**2. 分布式锁(可选)**

## 28. 秒杀接口限流实现

### 限流算法对比

| 算法 | 特点 | 适用场景 |
|------|------|----------|
| 令牌桶 | 允许突发流量,平滑限流 | 秒杀场景(推荐) |
| 漏桶 | 严格控制速率,无突发 | 匀速消费场景 |

### 1. 令牌桶算法实现(Guava RateLimiter)

```java
@Service
public class SeckillService {
    
    // 每秒生成1000个令牌
    private final RateLimiter rateLimiter = RateLimiter.create(1000);
    
    public Result<String> seckill(Long productId, Long userId) {
        // 尝试获取令牌,最多等待100ms
        if (!rateLimiter.tryAcquire(100, TimeUnit.MILLISECONDS)) {
            return Result.error("系统繁忙,请稍后重试");
        }
        
        // 执行秒杀逻辑
        return doSeckill(productId, userId);
    }
}
```

### 2. Redis + Lua实现滑动窗口限流

```java
String luaScript = 
    "local key = KEYS[1] " +
    "local limit = tonumber(ARGV[1]) " +
    "local window = tonumber(ARGV[2]) " +
    "local current = redis.call('incr', key) " +
    "if current == 1 then " +
    "    redis.call('expire', key, window) " +
    "end " +
    "if current > limit then " +
    "    return 0 " +
    "end " +
    "return 1";

public boolean allowRequest(String userId) {
    String key = "rate_limit:" + userId;
    Long result = redisTemplate.execute(
        new DefaultRedisScript<>(luaScript, Long.class),
        Collections.singletonList(key),
        "10",    // 10次请求
        "60"     // 60秒窗口
    );
    return result == 1;
}
```

## 29. RabbitMQ削峰填谷实现

### 核心作用

**1. 削峰**: 高并发请求先进队列,慢慢消费
**2. 异步**: 快速返回响应,提升用户体验
**3. 解耦**: 秒杀服务与订单服务解耦

### 实现方案

```java
// 1. 生产者 - 秒杀服务
@Service
public class SeckillProducer {
    
    @Autowired
    private RabbitTemplate rabbitTemplate;
    
    public void sendSeckillMessage(SeckillMessage message) {
        // 设置消息属性
        MessageProperties props = new MessageProperties();
        props.setDeliveryMode(MessageDeliveryMode.PERSISTENT); // 持久化
        props.setExpiration("60000"); // 60秒过期
        
        Message msg = new Message(
            JSON.toJSONBytes(message), 
            props
        );
        
        // 发送到秒杀队列
        rabbitTemplate.convertAndSend(
            "seckill.exchange",
            "seckill.order",
            msg
        );
    }
}

// 2. 消费者 - 订单服务
@Component
@RabbitListener(queues = "seckill.order.queue")
public class SeckillConsumer {
    
    @Autowired
    private OrderService orderService;
    
    @RabbitHandler
    public void handleMessage(SeckillMessage message) {
        try {
            // 创建订单
            orderService.createOrder(message);
            
        } catch (Exception e) {
            log.error("订单创建失败", e);
            // 重试或者记录到死信队列
            throw new AmqpRejectAndDontRequeueException(e);
        }
    }
}
```

```java
@Service
public class SeckillService {
    
    // Caffeine本地缓存
    private Cache<String, Integer> localCache = Caffeine.newBuilder()
        .maximumSize(10000)
        .expireAfterWrite(10, TimeUnit.SECONDS)
        .build();
    
    public Long decrStock(Long productId) {
        String key = "stock:" + productId;
        
        try {
            // 1. 优先从Redis获取
            return redisTemplate.opsForValue().decrement(key);
            
        } catch (Exception e) {
            log.error("Redis异常,使用本地缓存", e);
            
            // 2. Redis异常,使用本地缓存
            Integer stock = localCache.get(key, k -> {
                // 从数据库加载
                return stockMapper.getStock(productId);
            });
            
            if (stock != null && stock > 0) {
                localCache.put(key, stock - 1);
                return stock - 1L;
            }
            
            return -1L;
        }
    }
}
```

## 31. 秒杀全流程原子性保证

### 核心挑战
库存扣减、订单创建、支付三个步骤要么全成功,要么全失败。

### 解决方案

**方案1: 数据库事务(单体应用)**

```java
@Service
public class SeckillService {
    
    @Transactional(rollbackFor = Exception.class)
    public Order seckill(Long productId, Long userId) {
        
        // 1. 扣减库存(使用悲观锁)
        int rows = stockMapper.decrStockWithLock(productId, 1);
        if (rows == 0) {
            throw new StockNotEnoughException("库存不足");
        }
        
        // 2. 创建订单
        Order order = new Order();
        order.setProductId(productId);
        order.setUserId(userId);
        order.setStatus(OrderStatus.UNPAID);
        orderMapper.insert(order);
        
        // 3. 调用支付(同步)
        PayResult payResult = payService.pay(order);
        if (!payResult.isSuccess()) {
            throw new PayException("支付失败");
        }
        
        // 4. 更新订单状态
        order.setStatus(OrderStatus.PAID);
        orderMapper.updateStatus(order);
        
        return order;
    }
}
```

```java
// 第一阶段: Redis预减库存 + 发MQ
public Result seckill(Long productId, Long userId) {
    
    // 1. Redis预减库存
    Long stock = redisService.decrStock(productId);
    if (stock < 0) {
        return Result.error("库存不足");
    }
    
    // 2. 发送MQ消息
    SeckillMessage message = new SeckillMessage();
    message.setProductId(productId);
    message.setUserId(userId);
    message.setOrderId(IdGenerator.generate());
    
    mqProducer.send(message);
    
    return Result.success("排队中,请稍候查询结果");
}

// 第二阶段: 消费MQ创建订单
@RabbitListener(queues = "seckill.order.queue")
public void handleOrder(SeckillMessage message) {
    
    String lockKey = "order:lock:" + message.getOrderId();
    RLock lock = redisson.getLock(lockKey);
    
    try {
        // 分布式锁防止重复消费
        if (!lock.tryLock(5, 10, TimeUnit.SECONDS)) {
            return;
        }
        
        // 1. 扣减数据库库存
        int rows = stockMapper.decrStock(
            message.getProductId(), 1
        );
        
        if (rows == 0) {
            // 库存不足,回滚Redis
            redisService.incrStock(message.getProductId());
            
            // 发送失败通知
            notifyService.notifyFail(message.getUserId(), "库存不足");
            return;
        }
        
        // 2. 创建订单
        Order order = new Order();
        order.setOrderId(message.getOrderId());
        order.setProductId(message.getProductId());
        order.setUserId(message.getUserId());
        order.setStatus(OrderStatus.UNPAID);
        orderMapper.insert(order);
        
        // 3. 异步发起支付(发送到支付队列)
        payProducer.send(new PayMessage(order.getOrderId()));
        
        // 4. 通知用户订单创建成功
        notifyService.notifySuccess(
            message.getUserId(), 
            "订单创建成功,请尽快支付"
        );
        
    } catch (Exception e) {
        log.error("订单处理失败", e);
        
        // 回滚Redis库存
        redisService.incrStock(message.getProductId());
        
        // 重试或进入死信队列
        throw new RuntimeException(e);
        
    } finally {
        lock.unlock();
    }
}

// 第三阶段: 处理支付
@RabbitListener(queues = "pay.queue")
public void handlePay(PayMessage message) {
    
    try {
        // 1. 调用第三方支付
        PayResult result = thirdPayService.pay(message);
        
        if (result.isSuccess()) {
            // 2. 更新订单状态
            orderMapper.updateStatus(
                message.getOrderId(), 
                OrderStatus.PAID
            );
            
            // 3. 通知用户支付成功
            notifyService.notifyPaySuccess(message.getUserId());
            
        } else {
            // 支付失败,取消订单
            cancelOrder(message.getOrderId());
        }
        
    } catch (Exception e) {
        log.error("支付处理失败", e);
        // 支付异常,等待用户重试或订单超时取消
    }
}
```

```java
@Scheduled(fixedRate = 60000)
public void cancelUnpaidOrders() {
    List<Order> orders = orderMapper.selectUnpaidOrders(15); // 15分钟
    
    for (Order order : orders) {
        // 取消订单
        order.setStatus(OrderStatus.CANCELLED);
        orderMapper.updateStatus(order);
        
        // 回滚库存
        stockMapper.incrStock(order.getProductId(), order.getQuantity());
        redisService.incrStock(order.getProductId());
        
        // 通知用户
        notifyService.notifyCancel(order.getUserId());
    }
}

// 2. 支付回调幂等性保证
public void payCallback(PayCallbackDTO callback) {
    String lockKey = "pay:callback:" + callback.getOrderId();
    
    RLock lock = redisson.getLock(lockKey);
    try {
        lock.lock(10, TimeUnit.SECONDS);
        
        // 检查订单状态
        Order order = orderMapper.selectById(callback.getOrderId());
        if (order.getStatus() == OrderStatus.PAID) {
            return; // 已经处理过
        }
        
        // 更新订单
        order.setStatus(OrderStatus.PAID);
        orderMapper.updateStatus(order);
        
    } finally {
        lock.unlock();
    }
}
```

## 总结

秒杀系统的核心要点:

1. **高并发处理**: 多层限流 + 异步化
2. **库存准确性**: Redis原子操作 + 数据库兜底
3. **系统稳定性**: 熔断降级 + 消息削峰
4. **数据一致性**: 分布式事务 or 最终一致性
5. **高可用**: Redis集群 + 本地缓存兜底

实际生产中通常采用**异步最终一致性**方案,因为它性能最好,复杂度适中。
