# 面试实战二

## 1. Agent 循环流程是怎样的？

这道题考察你对大模型智能体工作原理的宏观理解。答题时要抓住感知、思考和行动这三个核心动作。  
简要描述 Agent 的循环流程：  
- **感知环境**：获取当前环境的状态信息。
- **思考决策**：根据模型进行推理和规划，确定要执行的动作。
- **行动执行**：调用工具或执行动作。
- **反馈**：将执行结果反馈给大模型，以便进行下一轮思考。

推荐提到 **ReAct 框架**，该框架将推理和行动结合，可以进一步增强回答的深度。

## 2. RAG 知识库选择了什么模型，调研过哪些模型？

这道题考察的是你是否有实践经验，并且了解模型的技术选型逻辑。  
答题时可分为两部分：
- **嵌入模型**：用于将文档转换为向量。常见的有 **BGE 系列**。
- **生成模型**：用于生成回答的模型。常见的有 **通义千问** 或 **Llama 系列**。

需要强调选型标准：
- 中文支持度
- 上下文窗口长度
- 部署成本

这样可以证明你选型时不仅关注技术，还考虑了实际应用的需求。

## 3. Redis 什么场景下会用分布式锁？

考察分布式系统下的并发安全问题。  
典型场景：
- **电商商品防超卖**：比如抢购秒杀场景。
- **定时任务防重复执行**：多个机器上运行定时任务时，避免同一个任务被重复执行。

可以提到使用 **setnx** 命令来实现分布式锁的基本原理。

## 4. 缓存和数据库的更新机制如何保证一致性？

这道题考察你对系统架构中数据一致性的理解。  
通常的做法是：
- **更新数据库**：首先保证数据库更新。
- **删除缓存**：随后删除缓存数据，这样缓存会在下一次请求时重新加载。

强调：
- **最终一致性**：我们追求的是最终一致性，而不是强一致性。
- 如果面试官进一步追问并发问题，可以提到**延迟双删**或**利用消息队列异步重试**来确保一致性。

## 5. 创建线程的方式，线程状态，sleep 和 wait 的区别，死锁的条件

考察基本的线程知识和死锁的理解。
- **创建线程的方式**：
  1. 继承 `Thread` 类
  2. 实现 `Runnable` 接口
  3. 实现 `Callable` 接口
  4. 使用线程池
- **线程状态**：
  - 新建
  - 就绪
  - 运行
  - 阻塞
  - 死亡
- **sleep 和 wait 的区别**：
  - `sleep`：不会释放锁，当前线程仅休眠。
  - `wait`：会释放锁，线程进入等待状态。
- **死锁的条件**：
  - 互斥
  - 请求与保持
  - 不剥夺
  - 循环等待

## 6. 网络分层模型七层模型，TCP 和 UDP 的区别，TCP 如何保证可靠性

考察网络基础知识。
- **七层模型**：
  1. 物理层
  2. 数据链路层
  3. 网络层
  4. 传输层
  5. 会话层
  6. 表示层
  7. 应用层
- **TCP 和 UDP 的区别**：
  - **TCP**：面向连接、可靠传输。
  - **UDP**：无连接、不可靠传输。
- **TCP 如何保证可靠性**：
  - **确认应答**（ACK）
  - **超时重传**
  - **滑动窗口**

## 7. 开放问题：如何理解 AI 编程对程序员的影响，AI 的到来会降低程序员的门槛吗？

此题考察行业洞察和软素质，答案没有标准答案，强调以下几点：
- **AI 提高工作效率**：AI 降低了初级程序员的代码编写门槛，是一个极好的提效工具。
- **AI 不能替代复杂业务理解**：AI 无法取代程序员对业务逻辑的深刻理解和系统架构设计能力。
- **未来趋势**：未来程序员需要掌握如何与 AI 协同工作，成为能够驾驭 AI 的人。
