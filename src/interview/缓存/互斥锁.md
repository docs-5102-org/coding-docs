# Redis 互斥锁：解决缓存击穿的完整教程

## 一、什么是缓存击穿问题

缓存击穿是指一个热点key在缓存中失效的瞬间，大量并发请求同时到达，这些请求会直接穿透缓存访问数据库，可能导致数据库瞬间压力过大甚至宕机。

**典型场景**：
- 商品详情页的热门商品信息
- 微博热搜榜单数据
- 秒杀活动的商品库存信息

## 二、解决方案概述

使用Redis互斥锁的核心思想是：**只允许一个线程去重建缓存，其他线程等待**。

### 方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 基础互斥锁 | 实现简单，保证只有一个线程查询DB | 其他线程需要等待，用户体验稍差 | 一般业务场景 |
| 提前更新锁 | 用户无感知，体验好 | 实现复杂，需要维护内部过期时间 | 对响应时间要求高的场景 |

## 三、方案一：基础互斥锁实现

### 3.1 实现原理

```
线程1: 缓存失效 → 获取锁成功 → 查询DB → 更新缓存 → 释放锁
线程2: 缓存失效 → 获取锁失败 → 等待 → 重试 → 从缓存获取数据
线程3: 缓存失效 → 获取锁失败 → 等待 → 重试 → 从缓存获取数据
```

### 3.2 Java 完整实现

```java
import redis.clients.jedis.Jedis;
import redis.clients.jedis.params.SetParams;

public class RedisMutexCache {
    
    private Jedis jedis;
    private static final String MUTEX_PREFIX = "mutex:";
    private static final int MUTEX_EXPIRE = 180; // 3分钟
    private static final int RETRY_DELAY = 50; // 毫秒
    private static final int MAX_RETRY = 10; // 最大重试次数
    
    /**
     * 获取缓存数据（带互斥锁）
     */
    public String getWithMutex(String key) {
        // 1. 尝试从缓存获取
        String value = jedis.get(key);
        
        if (value != null) {
            return value;
        }
        
        // 2. 缓存不存在，尝试获取互斥锁
        String mutexKey = MUTEX_PREFIX + key;
        
        if (tryLock(mutexKey)) {
            try {
                // 3. 获取锁成功，双重检查
                value = jedis.get(key);
                if (value != null) {
                    return value;
                }
                
                // 4. 从数据库加载数据
                value = loadFromDatabase(key);
                
                // 5. 写入缓存
                if (value != null) {
                    jedis.setex(key, 3600, value); // 设置1小时过期
                }
                
                return value;
                
            } finally {
                // 6. 释放锁
                releaseLock(mutexKey);
            }
        } else {
            // 7. 获取锁失败，等待后重试
            return retryGet(key, 0);
        }
    }
    
    /**
     * 尝试获取锁
     * 代码片段1 讲解
     * NX + EX 合在一个命令里，这是原子性的关键。
     */
    private boolean tryLock(String mutexKey) {
        SetParams params = new SetParams();
        params.nx(); // 只在key不存在时设置
        params.ex(MUTEX_EXPIRE); // 设置过期时间
        

        String result = jedis.set(mutexKey, "1", params); // 等价于 Redis 命令：SET mutexKey 1 NX EX 30
        return "OK".equals(result);
    }
    
    /**
     * 释放锁
     */
    private void releaseLock(String mutexKey) {
        jedis.del(mutexKey);
    }
    
    /**
     * 重试获取数据
     */
    private String retryGet(String key, int retryCount) {
        if (retryCount >= MAX_RETRY) {
            throw new RuntimeException("获取数据失败，超过最大重试次数");
        }
        
        try {
            Thread.sleep(RETRY_DELAY);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        
        // 重试时先检查缓存
        String value = jedis.get(key);
        if (value != null) {
            return value;
        }
        
        // 缓存仍然不存在，递归重试
        return getWithMutex(key);
    }
    
    /**
     * 从数据库加载数据（模拟）
     */
    private String loadFromDatabase(String key) {
        // 模拟数据库查询
        System.out.println("从数据库加载数据: " + key);
        try {
            Thread.sleep(100); // 模拟DB查询耗时
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        return "数据库中的值：" + key;
    }
}
```

#### 3.2.1 代码核心流程解析

这段代码实现了一个**防止缓存击穿**的互斥锁机制。让我详细讲解每个环节：

##### 1. **主流程 getWithMutex()**

```
查询缓存 → 缓存命中则返回
    ↓ 未命中
获取互斥锁
    ↓ 成功                    ↓ 失败
双重检查缓存              等待后重试
    ↓ 仍未命中
查询数据库
    ↓
写入缓存
    ↓
释放锁
```

##### 2. **关键设计点**

**双重检查（Double Check）**
```java
// 获取锁后再次检查缓存
value = jedis.get(key);
if (value != null) {
    return value;
}
```
- **目的**：防止多个线程竞争锁时，第一个线程已经加载了数据
- **避免**：重复查询数据库

**互斥锁设计**
```java
SetParams params = new SetParams();
params.nx();              // 只在key不存在时设置
params.ex(MUTEX_EXPIRE);  // 180秒过期
```
- **原子性**：SET NX EX 三个操作合一，防止死锁
- **自动过期**：即使线程崩溃，锁也会自动释放

**重试机制**
```java
Thread.sleep(RETRY_DELAY);  // 等待50毫秒
return getWithMutex(key);    // 递归重试
```
- **渐进式等待**：其他线程完成加载后，自己可以直接从缓存获取
- **最大重试限制**：防止无限等待

#### 与传统 SETNX 的区别

##### **当前代码方式（SET NX EX）**

```java
// 原子操作，一条命令完成
SetParams params = new SetParams().nx().ex(MUTEX_EXPIRE);
String result = jedis.set(mutexKey, "1", params);
```

**优点**：
- ✅ **原子性**：加锁和设置过期时间在一个命令完成
- ✅ **防止锁永久占用**：即使程序崩溃，锁也会自动过期
- ✅ **Redis 2.6.12+** 推荐方式

---

##### **传统 SETNX 方式**

```java
Long result = jedis.setnx(mutexKey, "1"); // 步骤 1：设置锁
if (result == 1) {
    jedis.expire(mutexKey, MUTEX_EXPIRE);  // 步骤 2：设置过期时间
}
```

**缺点**：
- ❌ **非原子性**：SETNX 成功后，如果进程崩溃（redis 网络阻塞、JVM 崩溃等），expire 未执行，于是锁没有设置过期时间 → 变成 永久存在的 key
- ❌ **死锁假象**：锁永久占用，其他线程永远等待
- ❌ **过时方式**：Redis 官方不推荐

:::tip
**为什么说是"非原子性"？**
关键理解：
原子性的定义原子性指的是：多个操作作为一个不可分割的整体执行，要么全部成功，要么全部失败，中间不会被打断。
虽然 setnx 和 expire 各自都是原子性的单条命令，但它们组合执行就不是原子性的了，存在时间间隙。

> Redis 官方文档的明确警告
> Warning: The pattern explained below is discouraged in favor of the Redlock algorithm which is only a bit ?>more complex to implement, but offers better guarantees and is fault tolerant.

Redis 官方文档明确指出：不推荐使用 SETNX + EXPIRE 的方式，应该使用原子性的 SET NX EX 命令。
:::

```java
import redis.clients.jedis.Jedis;
import redis.clients.jedis.params.SetParams;

/**
 * Redis 缓存互斥锁实现对比
 * 包含：SET NX EX（推荐）和 SETNX（不推荐）两种方式
 */
public class RedisMutexComparison {
    
    private Jedis jedis;
    private static final String MUTEX_PREFIX = "mutex:";
    private static final int MUTEX_EXPIRE = 180; // 3分钟
    private static final int RETRY_DELAY = 50;
    private static final int MAX_RETRY = 10;
    
    // ==================== 方式1：SET NX EX（推荐方式）====================
    
    /**
     * 推荐方式：使用 SET NX EX 原子操作
     * 优点：原子性、防死锁、安全可靠
     */
    public String getWithMutexRecommended(String key) {
        // 1. 尝试从缓存获取
        String value = jedis.get(key);
        if (value != null) {
            return value;
        }
        
        // 2. 缓存未命中，尝试获取互斥锁
        String mutexKey = MUTEX_PREFIX + key;
        
        if (tryLockRecommended(mutexKey)) {
            try {
                // 3. 双重检查
                value = jedis.get(key);
                if (value != null) {
                    return value;
                }
                
                // 4. 从数据库加载
                value = loadFromDatabase(key);
                
                // 5. 写入缓存
                if (value != null) {
                    jedis.setex(key, 3600, value);
                }
                
                return value;
                
            } finally {
                // 6. 释放锁
                releaseLock(mutexKey);
            }
        } else {
            // 7. 获取锁失败，等待重试
            return retryGet(key, 0);
        }
    }
    
    /**
     * 推荐：SET NX EX 原子操作获取锁
     */
    private boolean tryLockRecommended(String mutexKey) {
        SetParams params = new SetParams();
        params.nx();  // 只在key不存在时设置
        params.ex(MUTEX_EXPIRE);  // 设置过期时间（秒）
        
        String result = jedis.set(mutexKey, "1", params);
        return "OK".equals(result);
    }
    
    // ==================== 方式2：SETNX（不推荐，有死锁风险）====================
    
    /**
     * 不推荐方式：使用传统 SETNX
     * 缺点：非原子性、可能死锁、不安全
     */
    public String getWithMutexSetnx(String key) {
        // 1. 尝试从缓存获取
        String value = jedis.get(key);
        if (value != null) {
            return value;
        }
        
        // 2. 缓存未命中，尝试获取互斥锁
        String mutexKey = MUTEX_PREFIX + key;
        
        if (tryLockSetnx(mutexKey)) {
            try {
                // 3. 双重检查
                value = jedis.get(key);
                if (value != null) {
                    return value;
                }
                
                // 4. 从数据库加载
                value = loadFromDatabase(key);
                
                // 5. 写入缓存
                if (value != null) {
                    jedis.setex(key, 3600, value);
                }
                
                return value;
                
            } finally {
                // 6. 释放锁
                releaseLock(mutexKey);
            }
        } else {
            // 7. 获取锁失败，等待重试
            return retryGet(key, 0);
        }
    }
    
    /**
     * 不推荐：SETNX + EXPIRE 分离操作（非原子性）
     * 风险：如果 SETNX 后程序崩溃，EXPIRE 未执行，造成死锁
     */
    private boolean tryLockSetnx(String mutexKey) {
        Long result = jedis.setnx(mutexKey, "1");
        
        if (result == 1) {
            // ⚠️ 危险：这两步不是原子操作！
            // 如果在这里程序崩溃，锁永远不会过期
            jedis.expire(mutexKey, MUTEX_EXPIRE);
            return true;
        }
        
        return false;
    }
    
    // ==================== 方式3：SETNX 改进版（加入过期检查）====================
    
    /**
     * 改进方式：SETNX + 过期时间检查
     * 优点：一定程度避免死锁
     * 缺点：仍然不如 SET NX EX 简洁和可靠
     */
    public String getWithMutexSetnxImproved(String key) {
        String value = jedis.get(key);
        if (value != null) {
            return value;
        }
        
        String mutexKey = MUTEX_PREFIX + key;
        
        if (tryLockSetnxImproved(mutexKey)) {
            try {
                value = jedis.get(key);
                if (value != null) {
                    return value;
                }
                
                value = loadFromDatabase(key);
                
                if (value != null) {
                    jedis.setex(key, 3600, value);
                }
                
                return value;
                
            } finally {
                releaseLock(mutexKey);
            }
        } else {
            return retryGet(key, 0);
        }
    }
    
    /**
     * 改进：SETNX + 检查过期时间
     */
    private boolean tryLockSetnxImproved(String mutexKey) {
        Long result = jedis.setnx(mutexKey, "1");
        
        if (result == 1) {
            // 设置过期时间
            jedis.expire(mutexKey, MUTEX_EXPIRE);
            return true;
        } else {
            // 如果锁存在但没有过期时间（可能是死锁），设置过期时间
            Long ttl = jedis.ttl(mutexKey);
            if (ttl == -1) {  // -1 表示key存在但没有设置过期时间
                jedis.expire(mutexKey, MUTEX_EXPIRE);
            }
            return false;
        }
    }
    
    // ==================== 公共方法 ====================
    
    /**
     * 释放锁
     */
    private void releaseLock(String mutexKey) {
        jedis.del(mutexKey);
    }
    
    /**
     * 重试获取数据
     */
    private String retryGet(String key, int retryCount) {
        if (retryCount >= MAX_RETRY) {
            throw new RuntimeException("获取数据失败，超过最大重试次数");
        }
        
        try {
            Thread.sleep(RETRY_DELAY);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        
        // 重试时先检查缓存
        String value = jedis.get(key);
        if (value != null) {
            return value;
        }
        
        // 递归重试
        return getWithMutexRecommended(key);
    }
    
    /**
     * 从数据库加载数据（模拟）
     */
    private String loadFromDatabase(String key) {
        System.out.println("从数据库加载数据: " + key);
        try {
            Thread.sleep(100); // 模拟DB查询耗时
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
        return "数据库中的值：" + key;
    }

        RedisMutexComparison cache = new RedisMutexComparison();
        // cache.jedis = new Jedis("localhost", 6379);
        
        System.out.println("=== 方式1：SET NX EX（推荐）===");
        // String result1 = cache.getWithMutexRecommended("user:1001");
        
        System.out.println("\n=== 方式2：SETNX（不推荐）===");
        // String result2 = cache.getWithMutexSetnx("user:1002");
        
        System.out.println("\n=== 方式3：SETNX 改进版 ===");
        // String result3 = cache.getWithMutexSetnxImproved("user:1003");
    }
}
```

#### 使用建议

##### **生产环境请使用 SET NX EX**

```java
// 最佳实践
SetParams params = new SetParams().nx().ex(180);
jedis.set(mutexKey, "1", params);
```

##### **为什么不用 SETNX？**

1. **非原子性**：加锁和设置过期分离
2. **死锁风险**：程序崩溃时锁永久占用
3. **代码冗余**：需要额外的过期时间检查
4. **官方不推荐**：Redis 文档已明确说明

##### **实际应用场景**

- **缓存击穿**：热点数据过期时，只允许一个线程查DB
- **秒杀场景**：防止超卖，互斥扣减库存
- **分布式任务**：多实例环境下只执行一次

这段代码的核心价值在于**用空间换时间**：少数线程等待，换取数据库的稳定性。

```java
/**
 * 使用Lua脚本释放锁（避免误删其他线程的锁）

public class ImprovedRedisMutexCache {
    
    private static final String RELEASE_LOCK_SCRIPT = 
        "if redis.call('get', KEYS[1]) == ARGV[1] then " +
        "    return redis.call('del', KEYS[1]) " +
        "else " +
        "    return 0 " +
        "end";
    
    private boolean tryLockWithValue(String mutexKey, String requestId) {
        SetParams params = new SetParams();
        params.nx();
        params.ex(MUTEX_EXPIRE);
        
        String result = jedis.set(mutexKey, requestId, params);
        return "OK".equals(result);
    }
    
    private void releaseLockSafely(String mutexKey, String requestId) {
        jedis.eval(RELEASE_LOCK_SCRIPT, 
                   Collections.singletonList(mutexKey), 
                   Collections.singletonList(requestId));
    }
    
    public String getWithSafeMutex(String key) {
        String value = jedis.get(key);
        if (value != null) {
            return value;
        }
        
        String mutexKey = MUTEX_PREFIX + key;
        String requestId = UUID.randomUUID().toString();
        
        if (tryLockWithValue(mutexKey, requestId)) {
            try {
                value = jedis.get(key);
                if (value != null) {
                    return value;
                }
                
                value = loadFromDatabase(key);
                if (value != null) {
                    jedis.setex(key, 3600, value);
                }
                return value;
                
            } finally {
                releaseLockSafely(mutexKey, requestId);
            }
        } else {
            return retryGet(key, 0);
        }
    }
```

## 四、方案二：提前更新锁（高级方案）

### 4.1 实现原理

在缓存value中存储两个时间：
- **逻辑过期时间（timeout1）**：提前过期，触发更新
- **物理过期时间（timeout2）**：Redis实际过期时间，是timeout1的2倍

```
timeline: |----timeout1----|----timeout2----|
action:        触发更新        真正过期
```

### 4.2 数据结构设计

```java
/**
 * 缓存值对象（包含逻辑过期时间）
 */
public class CacheValue implements Serializable {
    private String data;           // 实际数据
    private long logicExpireTime;  // 逻辑过期时间（毫秒时间戳）
    
    public CacheValue(String data, long expireSeconds) {
        this.data = data;
        this.logicExpireTime = System.currentTimeMillis() + expireSeconds * 1000;
    }
    
    public boolean isExpired() {
        return System.currentTimeMillis() > logicExpireTime;
    }
    
    // getter/setter...
}
```

### 4.3 完整实现

```java
import com.fasterxml.jackson.databind.ObjectMapper;

public class RedisProactiveCache {
    
    private Jedis jedis;
    private ObjectMapper objectMapper = new ObjectMapper();
    
    private static final String MUTEX_PREFIX = "mutex:";
    private static final int LOGIC_EXPIRE = 3600;      // 逻辑过期：1小时
    private static final int PHYSICAL_EXPIRE = 7200;   // 物理过期：2小时
    private static final int MUTEX_EXPIRE = 180;       // 锁过期：3分钟
    
    /**
     * 获取数据（提前更新策略）
     */
    public String getWithProactiveUpdate(String key) {
        // 1. 从缓存获取
        String json = jedis.get(key);
        
        if (json == null) {
            // 2. 缓存完全不存在（首次访问或物理过期）
            return handleCacheMiss(key);
        }
        
        try {
            // 3. 解析缓存值
            CacheValue cacheValue = objectMapper.readValue(json, CacheValue.class);
            
            // 4. 检查是否逻辑过期
            if (!cacheValue.isExpired()) {
                // 未过期，直接返回
                return cacheValue.getData();
            }
            
            // 5. 逻辑已过期，尝试异步更新
            asyncUpdateCache(key, cacheValue);
            
            // 6. 返回旧数据（用户无感知）
            return cacheValue.getData();
            
        } catch (Exception e) {
            e.printStackTrace();
            return handleCacheMiss(key);
        }
    }
    
    /**
     * 处理缓存缺失
     */
    private String handleCacheMiss(String key) {
        String mutexKey = MUTEX_PREFIX + key;
        
        if (tryLock(mutexKey)) {
            try {
                // 双重检查
                String json = jedis.get(key);
                if (json != null) {
                    CacheValue cacheValue = objectMapper.readValue(json, CacheValue.class);
                    return cacheValue.getData();
                }
                
                // 从数据库加载
                String data = loadFromDatabase(key);
                
                // 写入缓存
                setCacheWithLogicExpire(key, data);
                
                return data;
                
            } catch (Exception e) {
                e.printStackTrace();
                return null;
            } finally {
                releaseLock(mutexKey);
            }
        } else {
            // 等待后重试
            try {
                Thread.sleep(50);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            return getWithProactiveUpdate(key);
        }
    }
    
    /**
     * 异步更新缓存
     */
    private void asyncUpdateCache(String key, CacheValue oldValue) {
        String mutexKey = MUTEX_PREFIX + key;
        
        // 尝试获取锁（非阻塞）
        if (tryLock(mutexKey)) {
            // 使用线程池异步执行
            CompletableFuture.runAsync(() -> {
                try {
                    // 1. 先延长旧数据的逻辑过期时间
                    oldValue.setLogicExpireTime(
                        System.currentTimeMillis() + MUTEX_EXPIRE * 1000
                    );
                    String extendedJson = objectMapper.writeValueAsString(oldValue);
                    jedis.setex(key, PHYSICAL_EXPIRE, extendedJson);
                    
                    // 2. 从数据库加载最新数据
                    String newData = loadFromDatabase(key);
                    
                    // 3. 更新缓存
                    setCacheWithLogicExpire(key, newData);
                    
                } catch (Exception e) {
                    e.printStackTrace();
                } finally {
                    releaseLock(mutexKey);
                }
            });
        }
        // 获取锁失败说明其他线程正在更新，直接返回即可
    }
    
    /**
     * 设置缓存（带逻辑过期时间）
     */
    private void setCacheWithLogicExpire(String key, String data) {
        try {
            CacheValue cacheValue = new CacheValue(data, LOGIC_EXPIRE);
            String json = objectMapper.writeValueAsString(cacheValue);
            jedis.setex(key, PHYSICAL_EXPIRE, json);
        } catch (Exception e) {
            e.printStackTrace();
        }
    }
    
    private boolean tryLock(String mutexKey) {
        SetParams params = new SetParams().nx().ex(MUTEX_EXPIRE);
        return "OK".equals(jedis.set(mutexKey, "1", params));
    }
    
    private void releaseLock(String mutexKey) {
        jedis.del(mutexKey);
    }
    
    private String loadFromDatabase(String key) {
        System.out.println("从数据库加载: " + key);
        // 模拟数据库查询
        return "DB数据:" + key + "_" + System.currentTimeMillis();
    }
}
```

### 5.2 缓存服务

```java
@Service
public class CacheService {
    
    @Autowired
    private RedisTemplate<String, Object> redisTemplate;
    
    @Autowired
    private UserMapper userMapper;
    
    /**
     * 获取用户信息（带互斥锁）
     */
    public User getUserById(Long userId) {
        String key = "user:" + userId;
        
        // 尝试从缓存获取
        User user = (User) redisTemplate.opsForValue().get(key);
        if (user != null) {
            return user;
        }
        
        // 缓存不存在，使用互斥锁
        String lockKey = "lock:user:" + userId;
        String lockValue = UUID.randomUUID().toString();
        
        try {
            // 尝试获取锁
            Boolean locked = redisTemplate.opsForValue()
                .setIfAbsent(lockKey, lockValue, 3, TimeUnit.MINUTES);
            
            if (Boolean.TRUE.equals(locked)) {
                // 获取锁成功
                try {
                    // 双重检查
                    user = (User) redisTemplate.opsForValue().get(key);
                    if (user != null) {
                        return user;
                    }
                    
                    // 从数据库查询
                    user = userMapper.selectById(userId);
                    
                    if (user != null) {
                        // 写入缓存
                        redisTemplate.opsForValue()
                            .set(key, user, 1, TimeUnit.HOURS);
                    }
                    
                    return user;
                    
                } finally {
                    // 释放锁（使用Lua脚本）
                    releaseLock(lockKey, lockValue);
                }
            } else {
                // 获取锁失败，等待后重试
                Thread.sleep(50);
                return getUserById(userId);
            }
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new RuntimeException("获取用户信息失败", e);
        }
    }
    
    /**
     * 安全释放锁
     */
    private void releaseLock(String lockKey, String lockValue) {
        String script = 
            "if redis.call('get', KEYS[1]) == ARGV[1] then " +
            "    return redis.call('del', KEYS[1]) " +
            "else " +
            "    return 0 " +
            "end";
        
        redisTemplate.execute(
            new DefaultRedisScript<>(script, Long.class),
            Collections.singletonList(lockKey),
            lockValue
        );
    }
}
```

**解决方案**：

### 7.2 锁误删问题

**问题**：线程A的锁过期后被线程B获取,线程A释放时删除了线程B的锁

**解决方案**：使用UUID标识锁的所有者（已在上面代码中实现）

### 7.3 缓存雪崩


## 八、总结

| 对比维度 | 基础互斥锁 | 提前更新锁 |
|---------|-----------|-----------|
| 实现难度 | ⭐⭐ | ⭐⭐⭐⭐ |
| 用户体验 | 可能有等待 | 无感知更新 |
| 系统复杂度 | 低 | 中等 |
| 适用场景 | 一般业务 | 高并发核心业务 |

**选择建议**：
- **中小型系统**：使用基础互斥锁方案即可
- **高并发系统**：使用提前更新锁方案，配合监控告警
- **特殊场景**：结合布隆过滤器防止缓存穿透
