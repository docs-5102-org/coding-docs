## Java基础概念

### JDK和JRE的区别

**JDK (Java Development Kit)** - Java开发工具包
- 提供Java的开发环境和运行环境
- 包含JRE + 编译器(javac) + 调试工具

**JRE (Java Runtime Environment)** - Java运行环境

- 包含JVM + 核心类库

**使用场景：**
- 只运行Java程序 → 安装JRE
- 开发Java程序 → 安装JDK

## 字符串相关

### == 和 equals 的区别

#### == 运算符

**基本类型：** 比较值是否相同

**引用类型：** 比较内存地址（引用）是否相同

```java
String x = "abc";           // 字符串常量池
String y = "abc";           // 指向同一个常量池对象
String z = new String("abc"); // 堆内存新对象

System.out.println(x == y);        // true（同一引用）
System.out.println(x == z);        // false（不同引用）
System.out.println(x.equals(y));   // true（值相同）
System.out.println(x.equals(z));   // true（值相同）
```

#### equals 方法

**默认行为：** 等同于 ==（比较引用）

**常见重写：** String、Integer等类重写为比较值

```java
// Object类中的默认实现
public boolean equals(Object obj) {
    return (this == obj);
}

// String类重写后的实现（简化版）
public boolean equals(Object anObject) {
    if (this == anObject) return true;
    if (anObject instanceof String) {
        String another = (String)anObject;
        // 逐字符比较
        return Arrays.equals(this.value, another.value);
    }
    return false;
}
```

**自定义类示例：**

```java
class Cat {
    private String name;
    
    public Cat(String name) {
        this.name = name;
    }
    
    // 未重写equals，使用默认实现
}

Cat c1 = new Cat("Tom");
Cat c2 = new Cat("Tom");
System.out.println(c1.equals(c2)); // false（比较引用）
```

**总结：**
- `==` 对基本类型比较值，对引用类型比较地址
- `equals` 默认比较地址，但常被重写为比较值

### hashCode 和 equals 的关系

**重要规则：**
1. 两个对象相等（equals为true），hashCode必须相同
2. hashCode相同，对象不一定相等（可能发生哈希冲突）

```java
String str1 = "通话";
String str2 = "重地";

System.out.println(str1.hashCode()); // 1179395
System.out.println(str2.hashCode()); // 1179395
System.out.println(str1.equals(str2)); // false
```

**原因：** 哈希算法可能产生碰撞，不同内容可能得到相同哈希值

### String的特性与限制

#### 运行时长度限制

**底层存储：** 使用char[]数组，长度由int类型记录

**理论最大长度：**
```
最大字符数：2³¹ - 1 = 2,147,483,647
内存占用：每个char占2字节（UTF-16编码）
最大内存：约4GB（实际JVM无法分配连续的4GB）
```

#### 编译时长度限制

**class文件限制：** 最多 65,534 字节

**原因：**
- class文件用16位无符号整数记录字符串长度（最大65536）
- 保留2字节给null值
- 实际可用：65,536 - 2 = 65,534字节

**编码影响：**
```java
// ASCII字符（1字节）
String str = "a..."; // 最多65,534个字符

// 中文字符（3字节）
String str = "你好..."; // 最多约21,844个字符
```

#### 超长字符串处理方案

**1. 拼接构造**
```java
String longStr = "part1..." + "part2..." + "part3...";
```

**2. StringBuilder构建**
```java
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 100000; i++) {
    sb.append("data");
}
String result = sb.toString();
```

**3. 外部加载**
```java
// 从文件读取
String content = Files.readString(Path.of("large.txt"));
```

**Android的TransactionTooLargeException：**
```java
// Binder限制：单次传输不超过1MB
// 通过Intent传递大字符串会抛出异常
// 解决方案：使用文件、数据库、EventBus等
```

### String、StringBuffer、StringBuilder

| 特性 | String | StringBuffer | StringBuilder |
|------|--------|--------------|---------------|
| 可变性 | 不可变 | 可变 | 可变 |
| 线程安全 | 安全 | 安全（synchronized） | 不安全 |
| 性能 | 较低 | 中等 | 最高 |
| 使用场景 | 少量字符串操作 | 多线程环境 | 单线程环境 |

**线程安全原理：**

```java
// StringBuffer的方法使用synchronized修饰
public synchronized StringBuffer append(String str) {
    super.append(str);
    return this;
}

// StringBuilder无同步机制
public StringBuilder append(String str) {
    super.append(str);
    return this;
}
```

**选择建议：**
- 字符串不变 → String
- 多线程修改 → StringBuffer
- 单线程修改 → StringBuilder（推荐）

### 数据类型相关

**String是基本类型吗？**

不是。Java有8种基本类型：
- 整型：byte, short, int, long
- 浮点型：float, double
- 字符型：char
- 布尔型：boolean

String是引用类型（对象）。

**字符常量 vs 字符串常量**

| 特性 | 字符常量 | 字符串常量 |
|------|----------|------------|
| 表示方式 | 单引号 `'a'` | 双引号 `"abc"` |
| 本质 | 整型值（ASCII/Unicode） | 内存地址 |
| 占用空间 | 2字节 | 可变（至少1字节） |
| 运算 | 可参与表达式运算 | 不可直接运算 |

```java
char c = 'A';           // 字符常量，值为65
String s = "Hello";     // 字符串常量，存储地址
```

## 面向对象

### final关键字的作用

**修饰类：** 类不能被继承（最终类）
```java
final class FinalClass {
    // 无法被继承
}
```

**修饰方法：** 方法不能被重写
```java
class Parent {
    final void method() {
        // 子类无法重写
    }
}
```

**修饰变量：** 变量成为常量，必须初始化且不可修改
```java
final int MAX_VALUE = 100;
// MAX_VALUE = 200; // 编译错误
```

### 抽象类相关

**抽象类必须有抽象方法吗？**

不一定。抽象类可以没有抽象方法。

```java
abstract class AbstractClass {
    public void concreteMethod() {
        System.out.println("普通方法");
    }
}
```

**抽象类 vs 普通类**

| 特性 | 抽象类 | 普通类 |
|------|--------|--------|
| 实例化 | 不能直接实例化 | 可以实例化 |
| 抽象方法 | 可以包含 | 不能包含 |
| 设计目的 | 作为基类被继承 | 直接使用 |

**抽象类能用final修饰吗？**

不能。final表示不可继承，与抽象类的设计目的矛盾。

### 接口 vs 抽象类

| 特性 | 接口 | 抽象类 |
|------|------|--------|
| 关键字 | implements | extends |
| 构造函数 | 无 | 有 |
| 实现数量 | 可实现多个 | 只能继承一个 |
| 方法默认修饰符 | public abstract | 任意修饰符 |
| 成员变量 | public static final | 任意修饰符 |
| 设计理念 | "能做什么"（行为） | "是什么"（本质） |

```java
// 接口
interface Flyable {
    void fly(); // 默认public abstract
}

// 抽象类
abstract class Animal {
    private String name;
    abstract void makeSound();
    public void eat() { }
}

// 使用
class Bird extends Animal implements Flyable {
    public void fly() { }
    void makeSound() { }
}
```

## IO流与NIO

### IO流的分类

**按功能分类：**
- 输入流（Input） - 读取数据
- 输出流（Output） - 写入数据

**按类型分类：**
- 字节流 - 8位传输，处理二进制数据
- 字符流 - 16位传输，处理文本数据

### BIO、NIO、AIO的区别

**BIO (Blocking IO)** - 同步阻塞IO
- 传统IO模型
- 一个连接一个线程
- 简单但并发能力低

**NIO (Non-blocking IO)** - 同步非阻塞IO
- 基于Channel和Buffer
- 一个线程处理多个连接（多路复用）
- 使用Selector监听事件

**AIO (Asynchronous IO)** - 异步非阻塞IO
- 基于事件和回调机制
- 操作完成后主动通知
- 真正的异步IO

### NIO核心组件

**1. Channel（通道）**
- 双向数据传输通道
- 类似流但更灵活

**2. Buffer（缓冲区）**
- 数据容器
- 读写数据的中转站

**3. Selector（选择器）**
- 单线程管理多个Channel
- 事件驱动模型

**工作流程：**
```
数据源 → Channel → Buffer → 应用程序
应用程序 → Buffer → Channel → 目标
```

**注意：** FileChannel无法设置为非阻塞模式，始终以阻塞模式运行。

### Files常用方法（NIO.2）

```java
// 文件检查
Files.exists(path);              // 检查是否存在
Files.isDirectory(path);         // 是否为目录

// 文件操作
Files.createFile(path);          // 创建文件
Files.createDirectory(path);     // 创建目录
Files.delete(path);              // 删除
Files.copy(source, target);      // 复制
Files.move(source, target);      // 移动

// 读写操作
Files.size(path);                // 获取大小
Files.readString(path);          // 读取内容（Java 11+）
Files.writeString(path, content);// 写入内容（Java 11+）
```

## 集合与数据结构

### HashSet如何检查重复

**检查流程：**

1. 计算对象的`hashCode()`
2. 查找是否有相同hashCode的对象
3. 如果有，调用`equals()`进一步比较
4. 都相同则认为重复，拒绝添加

```java
public boolean add(E e) {
    return map.put(e, PRESENT) == null;
}

// HashMap的put方法会：
// 1. 计算hash值
// 2. 找到对应位置
// 3. 调用equals比较key
```

**性能优化：** 通过hashCode快速定位，减少equals调用次数

**Math.round(-1.5) 等于多少？**

答案：**-1**

**规则：** 加0.5后向下取整
```
-1.5 + 0.5 = -1.0 → 向下取整 = -1
```

### 序列化

**阻止字段序列化：**

使用`transient`关键字修饰

```java
class User implements Serializable {
    private String username;
    private transient String password; // 不会被序列化
}
```

**特点：**
- 只能修饰变量，不能修饰类和方法
- 反序列化时，transient字段值为默认值（null/0/false）

### Java值传递

**重要结论：** Java中只有值传递，没有引用传递

**基本类型：** 传递值的副本
```java
void change(int x) {
    x = 10; // 不影响外部
}
```

**引用类型：** 传递引用的副本（地址值）
```java
void change(StringBuilder sb) {
    sb.append("!");  // 影响外部（操作同一对象）
    sb = new StringBuilder(); // 不影响外部（改变副本指向）
}
```

### Integer缓存机制

**缓存范围：** -128 到 127

```java
Integer i1 = 127;
Integer i2 = 127;
System.out.println(i1 == i2); // true（从缓存获取）

Integer i3 = 128;
Integer i4 = 128;
System.out.println(i3 == i4); // false（新建对象）

Integer i5 = new Integer(127);
Integer i6 = new Integer(127);
System.out.println(i5 == i6); // false（new强制创建新对象）
```

**原理：** 自动装箱时，范围内的值复用缓存对象，超出范围创建新对象

### valueOf() 方法就是 Integer 缓存的入口

当我们写 `Integer i = 100` 时，编译器会自动调用 `Integer.valueOf(100)` 方法完成自动装箱。

让我详细解释这个过程：

### 1. 自动装箱的底层机制

```java
// 我们写的代码
Integer i = 100;

// 编译器实际生成的字节码等价于
Integer i = Integer.valueOf(100);
```

### 2. valueOf() 方法的源码逻辑

```java
public static Integer valueOf(int i) {
    // 判断是否在缓存范围内 (-128 到 127)
    if (i >= IntegerCache.low && i <= IntegerCache.high)
        // 在范围内：直接返回缓存数组中的对象
        return IntegerCache.cache[i + (-IntegerCache.low)];
    // 超出范围：创建新对象
    return new Integer(i);
}
```

### 3. 为什么要 `i + (-IntegerCache.low)`？

这是**数组索引的映射**：

```java
// IntegerCache.low = -128
// cache 数组长度 = 256 (从 -128 到 127)

// 当 i = -128 时
索引 = -128 + (-(-128)) = -128 + 128 = 0

// 当 i = 0 时
索引 = 0 + (-(-128)) = 0 + 128 = 128

// 当 i = 127 时
索引 = 127 + (-(-128)) = 127 + 128 = 255
```

**目的**：将 -128~127 的值映射到数组索引 0~255

### 4. 完整的缓存初始化

```java
private static class IntegerCache {
    static final int low = -128;
    static final int high;  // 默认 127，可通过 JVM 参数配置
    static final Integer cache[];

    static {
        // 可以通过 -XX:AutoBoxCacheMax=<size> 配置上限
        int h = 127;
        String integerCacheHighPropValue =
            VM.getSavedProperty("java.lang.Integer.IntegerCache.high");
        if (integerCacheHighPropValue != null) {
            try {
                int i = parseInt(integerCacheHighPropValue);
                i = Math.max(i, 127);
                h = Math.min(i, Integer.MAX_VALUE - (-low) -1);
            } catch( NumberFormatException nfe) {
            }
        }
        high = h;

        // 创建缓存数组
        cache = new Integer[(high - low) + 1];
        int j = low;
        for(int k = 0; k < cache.length; k++)
            cache[k] = new Integer(j++);  // 预先创建 256 个对象
    }
}
```

### 5. 实际效果对比

```java
// 情况1：在缓存范围内
Integer a = 100;  // valueOf(100) -> 返回 cache[228]
Integer b = 100;  // valueOf(100) -> 返回 cache[228]
System.out.println(a == b);  // true（同一个对象）

// 情况2：超出缓存范围
Integer c = 200;  // valueOf(200) -> new Integer(200)
Integer d = 200;  // valueOf(200) -> new Integer(200)
System.out.println(c == d);  // false（不同对象）

// 情况3：强制 new
Integer e = new Integer(100);  // 不走 valueOf，直接 new
Integer f = new Integer(100);  // 不走 valueOf，直接 new
System.out.println(e == f);  // false（不同对象）

// 情况4：与基本类型比较
Integer g = 100;
int h = 100;
System.out.println(g == h);  // true（g 自动拆箱为 int）
```

### 6. 为什么要用缓存？

Java发现大部分数据操作都集中在较小的数值范围，因此在Java 5中新增了valueOf静态工厂方法，利用缓存机制带来明显的性能改进。

**性能优势：**
- 避免频繁创建小整数对象
- 减少内存占用
- 降低 GC 压力

**推荐做法：**
```java
// 推荐：使用 valueOf（走缓存）
Integer i = Integer.valueOf(100);

// 不推荐：直接 new（不走缓存，已废弃）
Integer i = new Integer(100);  // @Deprecated since JDK 9
```

### 总结

你找到的 `valueOf()` 方法确实就是 Integer 缓存的核心实现，所有自动装箱操作都会经过这个方法，从而实现了 -128 到 127 范围内整数对象的复用。

## 最佳实践总结

### 字符串操作
- 大量拼接用StringBuilder
- 多线程用StringBuffer
- 少量操作用String
- 避免在循环中用+拼接

### 对象比较
- 重写equals必须重写hashCode
- 集合类依赖hashCode和equals

### 异常处理
- 不要忽略异常
- 资源使用try-with-resources
- 自定义异常继承合适的父类

### 性能优化
- 合理使用缓存（如Integer缓存（IntegerCache））
- 避免不必要的对象创建
- 选择合适的集合类型
