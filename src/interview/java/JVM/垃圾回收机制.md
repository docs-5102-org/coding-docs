# 垃圾回收机制

## 概念

垃圾回收（Garbage Collection，简称 GC）是一种自动化的内存管理机制，它负责自动识别和释放程序中不再使用的对象所占用的内存空间。
垃圾回收器（Garbage Collector）会代替程序员手动进行内存管理，从而简化编程，并有效防止内存泄漏。


## 基本原理

GC 的核心任务可分为两个基本步骤： 

- 确定垃圾：找出内存中不再被任何程序部分引用的对象（即“垃圾”）。
- 释放内存：回收这些垃圾对象所占用的内存空间。

## 常见的垃圾回收算法

### 1. 标记-清除算法 (Mark-Sweep)

#### 工作原理
- **标记阶段**：从GC Roots开始遍历，标记所有可达的存活对象
- **清除阶段**：遍历堆内存，回收所有未被标记的对象

#### 优点
- 实现简单
- 不需要移动对象

#### 缺点
- **内存碎片**：清除后会产生大量不连续的内存碎片，可能导致大对象无法分配
- **效率问题**：标记和清除两个阶段效率都不高
- **STW（Stop The World）**：执行时需要暂停应用程序

#### 适用场景
老年代回收（CMS收集器使用）

---

### 2. 标记-复制算法 (Mark-Copy)

#### 工作原理
- 将内存分为两块相等的区域（From区和To区）
- 对象分配在From区
- GC时将From区存活对象复制到To区
- 清空From区，然后交换From和To区的角色

#### 优点
- **无内存碎片**：复制过程中会进行内存整理
- **分配效率高**：只需移动指针即可分配内存
- **回收效率高**：只需遍历存活对象

#### 缺点
- **空间浪费**：可用内存只有总内存的一半
- **复制开销**：存活对象较多时，复制开销大

#### 适用场景
新生代回收（因为新生代对象存活率低，复制对象少）

#### 改进版本：Eden + Survivor
```
HotSpot虚拟机默认Eden和Survivor比例为 8:1:1
- Eden区：80%
- Survivor0：10%
- Survivor1：10%
实际可用空间：90%
```

---

### 3. 标记-整理算法 (Mark-Compact)

#### 工作原理
- **标记阶段**：标记所有存活对象（同标记-清除）
- **整理阶段**：将所有存活对象向内存一端移动，然后清理边界外的内存

#### 优点
- **无内存碎片**：整理后内存连续
- **无空间浪费**：不需要额外的内存空间
- **适合存活率高的场景**：老年代对象存活率高

#### 缺点
- **移动对象开销大**：需要更新所有指向移动对象的引用
- **STW时间较长**：整理过程需要暂停应用

#### 适用场景
老年代回收

---

### 4. 分代收集算法 (Generational Collection)

#### 核心思想
根据对象存活周期将内存划分为不同代，针对不同代采用不同的回收算法

#### 分代策略
```
+---------------------------+
|     新生代 (Young Gen)     | → 标记-复制算法
|   - 对象存活率低 (~10%)    |   (Minor GC)
|   - 回收频繁               |
+---------------------------+
            ↓ (晋升)
+---------------------------+
|     老年代 (Old Gen)       | → 标记-清除 或
|   - 对象存活率高 (~90%)    |   标记-整理算法
|   - 回收较少               |   (Major GC)
+---------------------------+
```

#### 优点
- **针对性强**：不同代使用最适合的算法
- **整体效率高**：充分利用各算法优势

#### GC类型
- **Minor GC**：只回收新生代，频繁但快速
- **Major GC**：回收老年代
- **Full GC**：回收整个堆和方法区，耗时最长

---

### 5. 增量收集算法 (Incremental Collection)

#### 工作原理
将GC过程分解为多个小步骤，每次执行一小部分，与应用程序交替执行

#### 优点
- 减少单次GC停顿时间
- 改善用户体验

#### 缺点
- 总体GC时间增加
- 实现复杂
- 可能降低吞吐量

---

### 6. 并发收集算法 (Concurrent Collection)

#### 工作原理
GC线程与应用线程并发执行，尽量减少STW时间

#### 典型实现
- **CMS (Concurrent Mark Sweep)**
- **G1 (Garbage First)**
- **ZGC**
- **Shenandoah**

#### 优点
- **低延迟**：大幅减少停顿时间
- **适合大内存应用**

#### 缺点
- **CPU资源占用**：GC线程与应用线程竞争CPU
- **浮动垃圾**：并发标记时产生的新垃圾无法在本次回收
- **内存碎片**：某些实现可能产生碎片

---

### 算法对比表

```
+----------------+----------+----------+------------+----------------+
|     算法       | 内存碎片 | 空间利用 |  回收效率  |   适用场景     |
+----------------+----------+----------+------------+----------------+
| 标记-清除      |   有     |   高     |    中等    |    老年代      |
+----------------+----------+----------+------------+----------------+
| 标记-复制      |   无     |   低50%  |    高      |    新生代      |
+----------------+----------+----------+------------+----------------+
| 标记-整理      |   无     |   高     |    低      |    老年代      |
+----------------+----------+----------+------------+----------------+
| 分代收集       |   -      |   -      |    高      |  新生代+老年代 |
+----------------+----------+----------+------------+----------------+
```

### 算法流程图

```
标记-清除 (Mark-Sweep):
[对象A] [对象B] [对象C] [对象D] [对象E]
   ↓标记存活
[对象A] [对象B] [死亡] [对象D] [死亡]
   ↓清除
[对象A] [对象B] [空闲] [对象D] [空闲]  ← 产生碎片


标记-复制 (Mark-Copy):
From区: [对象A] [死亡] [对象C] [死亡]
          ↓ 复制存活对象
To区:   [对象A] [对象C] [空闲空间...]  ← 内存连续


标记-整理 (Mark-Compact):
整理前: [对象A] [死亡] [对象C] [死亡] [对象E]
          ↓ 标记并移动
整理后: [对象A] [对象C] [对象E] [空闲空间...]  ← 内存连续
```

### 选择建议

- **追求吞吐量**：Parallel GC（标记-整理/标记-复制）
- **追求低延迟**：CMS、G1、ZGC（并发标记）
- **内存受限**：标记-整理（无空间浪费）
- **新生代**：标记-复制（对象少，复制快）
- **老年代**：标记-清除或标记-整理（对象多，存活率高）

## 分代垃圾回收器工作原理?

### 核心思想
分代垃圾回收器基于"大部分对象朝生夕死"的假设，将堆内存划分为不同区域，针对不同生命周期的对象采用不同的回收策略。

### 内存分区

<img src="/assets/images/jvm/image6.png" style="width: 800px;"></img>

#### 整体划分
- **新生代（Young Generation）**：占总堆内存的 1/3，新创建的对象首先分配在Eden区，经过多次GC后仍存活的对象会移至Survivor区，最终晋升到老年代。
- **老年代（Old Generation）**：占总堆内存的 2/3，存放生命周期较长的对象，GC频率较低但耗时较长。

#### 新生代细分
新生代采用**复制算法**，空间占比为：`8:1:1`，内部分为三个区域：
- **Eden 区**：占新生代的 8/10
- **Survivor From 区**：占新生代的 1/10  
- **Survivor To 区**：占新生代的 1/10

---

### 工作流程

<img src="/assets/images/jvm/image7.png" style="width: 800px;"></img>

#### Minor GC（新生代回收）
1. **对象分配**：新对象优先在 Eden 区分配
2. **触发回收**：当 Eden 区满时触发 Minor GC
3. **复制存活对象**：将 Eden 区和 From Survivor 区中的存活对象复制到 To Survivor 区
4. **清空区域**：清空 Eden 区和 From Survivor 区
5. **角色互换**：From Survivor 和 To Survivor 互换角色

#### 对象晋升机制
- **年龄增长**：每经历一次 Minor GC 仍存活的对象，年龄 +1
- **晋升老年代**：年龄达到阈值（默认 15）时，晋升到老年代
- **大对象直接进入**：超过一定大小的对象直接分配到老年代

#### Major GC / Full GC（老年代回收）
- **触发时机**：老年代空间不足时触发
- **回收算法**：一般使用**标记-整理算法**（Mark-Compact）
- **特点**：回收范围大，耗时较长，会造成较明显的停顿
