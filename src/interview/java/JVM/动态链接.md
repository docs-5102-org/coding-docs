# 动态链接

## 什么是动态链接？

动态链接是栈帧中的一个组成部分，它**存储了一个指针/引用，指向运行时常量池中当前方法的符号引用**。

## 为什么需要动态链接？

在Java程序运行过程中，方法之间会相互调用。这些调用关系需要在运行时被正确解析和执行。动态链接就是实现这一机制的关键。

## 详细工作原理

### 1. **编译阶段**
```java
public class Example {
    public void methodA() {
        methodB();  // 调用methodB
    }
    
    public void methodB() {
        System.out.println("Hello");
    }
}
```

编译后，`methodA`中对`methodB`的调用会被记录为**符号引用**，存储在class文件的常量池中，例如：
- `#15 = Methodref  #3.#16`  (指向methodB的符号引用)

### 2. **运行时结构**

```
栈帧（methodA）
├─ 局部变量表
├─ 操作数栈
├─ 动态链接 ──────┐
└─ 方法返回地址    │
                   │
                   ↓
运行时常量池
├─ #1: Class "Example"
├─ #2: Methodref "methodA"
├─ #3: Methodref "methodB"  ← 指向这里
├─ #4: String "Hello"
└─ ...
```

### 3. **两种链接方式**

#### **静态链接（Static Linking）**
- 在**类加载时**就能确定的方法调用
- 适用于：
  - `static` 方法
  - `private` 方法
  - `final` 方法
  - 构造方法
  - 父类方法
  
```java
public class Test {
    private void privateMethod() { }
    public static void staticMethod() { }
    public final void finalMethod() { }
}
```

这些方法的调用地址在编译期就能确定，**符号引用在类加载时转换为直接引用**。

#### **动态链接（Dynamic Linking）**
- 在**每次运行时**才确定的方法调用
- 适用于：需要**动态分派**的方法（多态调用）

```java
public class Animal {
    public void speak() {
        System.out.println("Animal sound");
    }
}

public class Dog extends Animal {
    @Override
    public void speak() {
        System.out.println("Woof!");
    }
}

public class Test {
    public void test(Animal animal) {
        animal.speak();  // 运行时才知道调用哪个speak()
    }
}
```

### 4. **符号引用 vs 直接引用**

```
【符号引用】
- 一组符号来描述引用的目标
- 与虚拟机内存布局无关
- 例如: "com/example/MyClass.myMethod()V"

                ↓ 解析过程

【直接引用】
- 直接指向目标的指针、偏移量或句柄
- 与虚拟机内存布局相关
- 例如: 内存地址 0x7f8a3c001000
```

## 完整执行流程示例

```java
public class Demo {
    public void caller() {
        Dog dog = new Dog();
        dog.speak();  // ← 这里发生动态链接
    }
}
```

**执行步骤：**

1. **栈帧创建**：`caller()`方法被调用，创建栈帧
2. **动态链接字段**：指向常量池中`Dog.speak()`的符号引用
3. **符号引用解析**：
   - 第一次调用时，根据对象实际类型（Dog）
   - 查找Dog类的方法表
   - 找到`speak()`方法的直接引用（内存地址）
   - 后续调用可能会缓存这个结果（内联缓存）
4. **方法调用**：跳转到目标方法地址执行

## 图解完整过程

```
调用 dog.speak()
     ↓
栈帧（caller方法）
┌──────────────────┐
│ 局部变量表       │
│ dog = [Dog对象]  │
├──────────────────┤
│ 操作数栈         │
├──────────────────┤
│ 动态链接         │ ───┐
│ (指向常量池)     │    │
└──────────────────┘    │
                        ↓
运行时常量池              
┌─────────────────────────┐
│ #10: Methodref          │
│      Animal.speak()     │ ← 符号引用
└─────────────────────────┘
                        ↓
                    【解析过程】
                        ↓
    检查dog的实际类型 → Dog
                        ↓
        查找Dog的方法表
                        ↓
┌─────────────────────────┐
│ Dog类的方法表           │
│ - speak() → 0x1A2B3C    │ ← 直接引用（内存地址）
└─────────────────────────┘
                        ↓
            跳转到该地址执行
```

## 为什么叫"动态"？

因为对于多态方法调用，**只有在运行时才能根据对象的实际类型确定调用哪个方法的实现**。这个解析过程是动态的，不是编译时固定的。

## 总结

**动态链接的核心作用：**
1. 连接栈帧与常量池，建立方法调用的桥梁
2. 支持Java的多态特性（运行时方法分派）
3. 在运行时将符号引用转换为直接引用
4. 每个栈帧都有自己的动态链接，指向自己所属方法的引用信息

这就是为什么Java能够实现面向对象的多态性——通过动态链接机制，在运行时根据对象的实际类型来确定调用哪个方法。
