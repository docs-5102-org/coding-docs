# Java JDK 代理实现与原理详解

> 静态代理 · 动态代理 · InvocationHandler · Proxy · CGLib

---

## 前言

在 Java 中谈到代理，首先需要了解一种经典的设计模式——**代理模式**。根据代理类的创建时机，代理可分为两类：

- **静态代理**：在编译阶段就已确定代理类，由程序员手动编写或工具自动生成。
- **动态代理**：在程序运行时，借助反射机制动态创建代理类。

本文将围绕这两类代理，结合代码示例，由浅入深地讲解其实现原理与使用场景。

---

## 代理模式

代理模式是 Java 中常用的设计模式，其核心特征是：**代理类与委托类（被代理类）拥有相同的接口**。代理类本身不直接执行业务逻辑，而是通过调用委托类的方法来提供服务，同时可在调用前后插入额外处理（如日志、权限校验、事务管理等）。

这种「间接性」带来的好处包括：

- **解耦**：调用方只依赖接口，无需关心具体实现。
- **扩展性**：可在不修改原有类的情况下，为其附加新功能。
- **复用性**：一个代理类可以同时代理多个实现了相同接口的类。

---

## 一、静态代理

### 1.1 概念

静态代理指代理类在**编译期**就已确定。程序员需要手动为每个委托类编写对应的代理类，代理类与委托类实现同一接口。

> 💡 **优点**：实现简单，易于理解。**缺点**：每个委托类都需要一个代理类，代码冗余；若接口新增方法，代理类也需同步修改。

### 1.2 示例：王婆、潘金莲与西门庆

以下示例用通俗故事来演示静态代理：西门庆（调用方）通过王婆（代理）来与潘金莲（委托类）交互。

#### ① 定义公共接口 KindWomen

接口代表「这一类型的女人」，代理类与委托类都须实现此接口：

```java
package com.master.proxy;

/**
 * 定义接口：代理类与委托类的共同契约
 */
public interface KindWomen {
    void makeEyesWithMan();          // 抛媚眼
    void happyWithMan();              // 相处
    void dragonEnteredShuangFeng();
}
```

#### ② 委托类：潘金莲

```java
package com.master.proxy;

public class PanJinLian implements KindWomen {

    @Override
    public void makeEyesWithMan() {
        System.out.println("潘金莲：抛媚眼");
    }

    @Override
    public void happyWithMan() {
        System.out.println("潘金莲：happyWithMan");
    }

    @Override
    public void dragonEnteredShuangFeng() {
        System.out.println("潘金莲：dragonEnteredShuangFeng");
    }
}
```

#### ③ 代理类：王婆

王婆实现了同一接口，持有委托类引用，在调用前后可插入额外逻辑：

```java
package com.master.proxy;

public class WangPo implements KindWomen {

    private KindWomen kindWomen;

    /** 默认代理潘金莲 */
    public WangPo() {
        this.kindWomen = new PanJinLian();
    }

    /** 可灵活切换被代理对象（面向接口编程） */
    public WangPo(KindWomen kindWomen) {
        this.kindWomen = kindWomen;
    }

    @Override
    public void makeEyesWithMan() {
        this.kindWomen.makeEyesWithMan();
    }

    @Override
    public void happyWithMan() {
        this.kindWomen.happyWithMan();
    }

    @Override
    public void dragonEnteredShuangFeng() {
        this.kindWomen.dragonEnteredShuangFeng();
    }
}
```

#### ④ 调用方：西门庆

```java
package com.master.proxy;

public class XiMenQing {

    public static void main(String[] args) {
        // 场景一：代理潘金莲
        WangPo wangPo = new WangPo();
        wangPo.makeEyesWithMan();
        wangPo.happyWithMan();

        // 场景二：切换委托对象为贾氏，代理类无需修改
        JiaShi jiaShi = new JiaShi();
        WangPo wangPo2 = new WangPo(jiaShi);
        wangPo2.makeEyesWithMan();
        wangPo2.happyWithMan();
    }
}
```

> 📌 **静态代理的本质**：通过多态（面向接口编程）实现解耦。代理类与委托类「同根同源」——实现同一接口，彼此知根知底。

## 二、动态代理

### 2.1 概念与优势

动态代理在程序**运行时**通过反射机制动态生成代理类，无需为每个委托类手动编写代理代码。

对比静态代理的痛点——若要在每个方法调用前统一执行某段逻辑（如权限检查、日志记录），静态代理需要在每个方法中重复编写，而动态代理只需在一处统一处理，大大提升了代码的可维护性。

> 💡 **实现原理**：运用 `java.lang.reflect` 包中的 `Proxy` 类和 `InvocationHandler` 接口，在运行时动态生成代理类的字节码并加载到 JVM。

### 2.2 典型应用场景

- **Spring AOP**：方法拦截、事务管理、日志记录
- **Hibernate**：延迟加载、数据查询优化
- **测试框架**：Mock 对象生成
- **RPC 框架**：远程服务调用
- **注解处理**：动态获取和处理注解

### 2.3 实现方式概览

Java 中动态代理主要有两种实现方式：**JDK 动态代理**和 **CGLib 动态代理**。

| 特性 | JDK 动态代理 | CGLib 动态代理 |
|---|---|---|
| 实现方式 | 基于接口 | 基于继承（生成子类） |
| 目标类要求 | 必须实现接口 | 不能是 final 类 |
| 性能 | 调用效率略低 | 调用效率较高 |
| 包依赖 | JDK 自带 | 需引入 CGLib 库 |

---

### 2.4 JDK 动态代理

#### 核心 API

**InvocationHandler 接口**

所有对代理对象的方法调用，最终都会被转发到 `InvocationHandler.invoke()` 方法：

```java
package java.lang.reflect;

public interface InvocationHandler {
    /**
     * @param proxy  代理对象本身（很少直接使用）
     * @param method 被调用的方法对象
     * @param args   方法调用时传入的参数
     */
    Object invoke(Object proxy, Method method, Object[] args) throws Throwable;
}
```

**Proxy 类**

`Proxy.newProxyInstance()` 是创建动态代理对象的入口方法：

```java
public static Object newProxyInstance(
    ClassLoader loader,       // 类加载器，用于加载生成的代理类
    Class<?>[] interfaces,    // 代理类需要实现的接口列表
    InvocationHandler h       // 方法调用处理器
) throws IllegalArgumentException
```

**类加载器说明**

`newProxyInstance` 需要传入一个类加载器，Java 主要有以下三类：

| 类加载器 | 说明 |
|---|---|
| Bootstrap ClassLoader | C++ 实现，负责加载 JDK 核心类库（rt.jar 等），开发者通常不可见 |
| Extension ClassLoader | 负责加载 `jre/lib/ext` 目录下的扩展类 |
| AppClassLoader（默认） | 负责加载 classpath 下的应用类，日常开发最常用 |

#### 示例：动态代理版王婆

将静态代理示例改造为动态代理，王婆现在可以「动态」代理任何实现了 `KindWomen` 接口的对象。

**① 实现 InvocationHandler**

```java
package com.master.proxy;

import java.lang.reflect.InvocationHandler;
import java.lang.reflect.Method;
import java.lang.reflect.Proxy;

/**
 * 动态代理处理器：可代理所有实现了 KindWomen 接口的对象
 */
public class WangPoInvocationHandler implements InvocationHandler {

    private Object target; // 被代理的目标对象

    /** 绑定委托对象，返回动态生成的代理对象 */
    public Object bind(Object target) {
        this.target = target;
        return Proxy.newProxyInstance(
            target.getClass().getClassLoader(),  // 使用委托类的类加载器
            target.getClass().getInterfaces(),   // 实现委托类的所有接口
            this                                  // 当前 handler
        );
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        // ✅ 统一的前置处理（只需写一次）
        System.out.println("[代理] 调用方法：" + method.getName());
        // 执行目标方法
        Object result = method.invoke(target, args);
        // ✅ 统一的后置处理（只需写一次）
        System.out.println("[代理] 方法执行完成");
        return result;
    }
}
```

**② 调用方：西门庆**

```java
package com.master.proxy;

public class XiMenQing {

    public static void main(String[] args) {
        WangPoInvocationHandler handler = new WangPoInvocationHandler();

        // 动态代理潘金莲
        KindWomen panProxy = (KindWomen) handler.bind(new PanJinLian());
        panProxy.happyWithMan();

        // 无需修改代理逻辑，直接切换到贾氏
        KindWomen jiaProxy = (KindWomen) handler.bind(new JiaShi());
        jiaProxy.happyWithMan();
    }
}
```

### 2.5 CGLib 动态代理

CGLib 通过**生成目标类的子类**并覆盖其方法来实现代理，因此目标类无需实现任何接口。

> ⚠️ **注意**：由于采用继承方式，CGLib **无法代理 `final` 修饰的类或方法**。

#### 核心用法

```java
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserServiceImpl.class); // 设置父类为目标类
enhancer.setCallback(new CglibProxyInterceptor()); // 设置方法拦截器
UserServiceImpl proxy = (UserServiceImpl) enhancer.create();
```

#### 示例：田弘与陈圆圆

陈圆圆无需实现任何接口，CGLib 直接为其生成子类代理：

**① 委托类：陈圆圆（无需实现接口）**

```java
package com.master.proxy;

/**
 * 陈圆圆：不需要实现接口，CGLib 直接对普通类进行代理
 */
public class ChenYuanYuan {

    public void makeEyesWithMan() {
        System.out.println("makeEyesWithMan：makeEyesWithMan");
    }

    public void happyWithMan() {
        System.out.println("happyWithMan：papapa");
    }

    public void dragonEnteredShuangFeng() {
        System.out.println("dragonEnteredShuangFeng：hahaha");
    }
}
```

**② CGLib 代理类：田弘**

```java
package com.master.proxy;

import org.springframework.cglib.proxy.Enhancer;
import org.springframework.cglib.proxy.MethodInterceptor;
import org.springframework.cglib.proxy.MethodProxy;

import java.lang.reflect.Method;

/**
 * 田弘：CGLib 代理实现，可代理未实现接口的普通类
 */
public class TianHongCglib implements MethodInterceptor {

    private Object target; // 被代理的目标对象

    /** 绑定委托对象，返回 CGLib 动态生成的代理对象 */
    public Object bind(Object target) {
        this.target = target;
        Enhancer enhancer = new Enhancer();
        enhancer.setSuperclass(this.target.getClass()); // 设置父类为目标类
        enhancer.setCallback(this);                      // 设置回调拦截器
        return enhancer.create();
    }

    @Override
    public Object intercept(Object obj, Method method, Object[] args, MethodProxy proxy) throws Throwable {
        System.out.println("intercept：" + obj.getClass().getName());
        System.out.println("方法执行前...");
        Object result = proxy.invokeSuper(obj, args);   // 调用父类（目标类）方法
        System.out.println("方法执行后...");
        return result;
    }
}
```

**③ 调用方：吴三桂**

```java
package com.master.proxy;

public class WuSanGui {

    public static void main(String[] args) {
        TianHongCglib cglib = new TianHongCglib();
        ChenYuanYuan chenYuanYuan = (ChenYuanYuan) cglib.bind(new ChenYuanYuan());
        chenYuanYuan.happyWithMan();
    }
}
```

## 三、静态代理 vs 动态代理

| 对比维度 | 静态代理 | JDK 动态代理 | CGLib 动态代理 |
|---|---|---|---|
| 代理类生成时机 | 编译期 | 运行时（反射） | 运行时（字节码增强） |
| 目标类要求 | 实现接口 | 必须实现接口 | 不能是 final 类 |
| 代码量 | 每个委托类需单独编写代理类 | 一个 Handler 代理多个类 | 一个 Interceptor 代理多个类 |
| 灵活性 | 差，接口变化需同步修改 | 高，统一处理所有方法 | 高，统一处理所有方法 |
| 性能 | 最高（无反射） | 略低（反射调用） | 较高（现代版本已优化） |
| 典型应用场景 | 简单场景、代理类数量少 | Spring AOP（接口场景） | Spring AOP（无接口场景） |

---

## 四、总结

代理模式通过引入间接层，实现了调用方与实现方的解耦，是 AOP（面向切面编程）的基础。

- **静态代理** 适合代理对象少、接口稳定的简单场景。
- **JDK 动态代理** 适合委托类已实现接口的场景，是 Spring AOP 的默认实现方式。
- **CGLib 动态代理** 可对未实现接口的普通类进行代理（通过继承实现），弥补了 JDK 动态代理的不足。

> 🚀 在实际项目中，优先使用动态代理（或直接使用 Spring AOP），避免手动编写大量静态代理类，保持代码简洁可维护。
