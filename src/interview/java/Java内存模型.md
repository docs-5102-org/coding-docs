# Java内存模型详解

## 定义与目的

Java内存模型（Java Memory Model, JMM）是Java虚拟机规范中定义的一种抽象概念，用于屏蔽各种硬件和操作系统的内存访问差异，确保Java程序在不同平台下都能实现一致的并发内存访问效果。

在JMM出现之前，C/C++等语言直接使用物理硬件和操作系统的内存模型，这导致同一程序在不同平台上可能表现出不同的并发行为。Java通过JMM解决了这一问题。

**发展历程：** JDK 1.5（JSR-133）对JMM进行了重要改进和完善，修复了早期版本的诸多问题，使其更加成熟可靠。

## 主内存与工作内存

JMM定义了线程和主内存之间的抽象关系：

- **主内存（Main Memory）**：存储所有共享变量（实例字段、静态字段、数组元素）
- **工作内存（Working Memory）**：每个线程独有，存储该线程使用的变量的副本

**重要规则：**
- 线程对变量的所有操作必须在工作内存中进行
- 不同线程之间无法直接访问对方的工作内存
- 线程间变量传递必须通过主内存完成
- 局部变量和方法参数不属于共享变量，它们是线程私有的

## 内存间的八种交互操作

JMM定义了以下八种原子操作来完成主内存与工作内存之间的交互：

| 操作 | 作用域 | 说明 |
|------|--------|------|
| **lock** | 主内存 | 将变量标识为线程独占状态 |
| **unlock** | 主内存 | 释放锁定状态的变量 |
| **read** | 主内存 | 将变量值传输到工作内存 |
| **load** | 工作内存 | 将read的值放入工作内存副本 |
| **use** | 工作内存 | 将变量值传递给执行引擎 |
| **assign** | 工作内存 | 将执行引擎的值赋给工作内存变量 |
| **store** | 工作内存 | 将变量值传送到主内存 |
| **write** | 主内存 | 将store的值写入主内存变量 |

**操作规则：**
- read和load、store和write必须成对顺序出现，但不必连续执行
- 变量修改后必须同步回主内存（不允许丢弃assign操作）
- 不允许无故将未修改的数据同步回主内存
- 新变量只能在主内存中创建
- 一个变量同一时刻只允许一个线程lock
- lock操作会清空工作内存中的变量值
- unlock前必须先将变量同步回主内存


##  lock/unlock 的触发条件

```
════════════════════════════════════════════════════════════════
                    lock/unlock 的触发条件
════════════════════════════════════════════════════════════════

【会触发 lock/unlock 的情况】

1. synchronized 关键字
   synchronized(obj) {
       // lock(obj) - 锁定主内存中的obj
       // ... 操作 ...
       // unlock(obj) - 解锁
   }

2. ReentrantLock 等显式锁
   lock.lock();
   // lock 操作
   try {
       // ... 操作 ...
   } finally {
       lock.unlock();  // unlock 操作
   }


【不会触发 lock/unlock 的情况】

普通变量读写（没有同步）：
   int x = 10;        // 只有 assign → store → write
   int y = x;         // 只有 read → load → use
   ❌ 不会有 lock/unlock


volatile 变量：
   volatile int count = 0;
   count++;           // 只保证可见性和有序性
   ❌ 也不会有 lock/unlock（volatile不保证原子性）


════════════════════════════════════════════════════════════════
                        内存操作对比
════════════════════════════════════════════════════════════════

【普通变量】
Thread1: assign → store → write
              ↓
         主内存（可能延迟）
              ↓
Thread2: read → load → use (可能读到旧值)


【synchronized同步】
Thread1: lock → assign → store → write → unlock
              ↓
         主内存（强制刷新）
              ↓
Thread2: lock → read → load → use → unlock (保证读到新值)


【volatile变量】
Thread1: assign → store → write (立即刷新)
              ↓
         主内存（保证可见）
              ↓
Thread2: read → load → use (保证读到新值)
❌ 但没有 lock/unlock，所以 count++ 不是原子的！
```

**总结：**

| 方式 | lock/unlock | 可见性 | 原子性 | 有序性 |
|------|-------------|--------|--------|--------|
| 普通变量 | ❌ 无 | ❌ | ❌ | ❌ |
| volatile | ❌ 无 | ✅ | ❌ | ✅ |
| synchronized | ✅ 有 | ✅ | ✅ | ✅ |
| Lock | ✅ 有 | ✅ | ✅ | ✅ |

**lock/unlock 是 JMM 定义的 8 种操作之一，但只有在使用同步机制时才会实际执行**！
