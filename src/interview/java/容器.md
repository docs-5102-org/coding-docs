Java容器主要分为两大类：Collection和Map

## 二、核心概念

### 2.1 Collection vs Collections

- **Collection**：集合接口，提供了对集合对象进行基本操作的通用接口方法，所有集合都是它的子类，如List、Set等
- **Collections**：工具类，包含很多静态方法，不能被实例化，提供如`Collections.sort(list)`等实用方法

### 2.2 List、Set、Map的区别

| 特性 | List | Set | Map |
|------|------|-----|-----|
| 元素是否有序 | 有序 | 无序 | 无序 |
| 是否允许重复 | 允许 | 不允许 | Key不允许，Value允许 |
| 主要实现类 | ArrayList、LinkedList、Vector | HashSet、TreeSet | HashMap、TreeMap、Hashtable |

## 三、HashMap详解

### 3.1 数据结构

HashMap采用**数组+链表+红黑树**的混合结构：

- **JDK 1.7及之前**：数组+链表
- **JDK 1.8及之后**：数组+链表+红黑树（当链表长度超过8时转为红黑树）

好的,我来用 ASCII 画出 HashMap 的结构:

```

数组(桶/bucket)
```

**关键点说明**:
- 数组是 HashMap 的主干,通过 hash 值定位到具体的桶
- 每个桶可能是:空/单节点/链表/红黑树
- 链表长度 ≤ 8 时保持链表结构
- 链表长度 > 8 且数组长度 ≥ 64 时转为红黑树
- 红黑树节点减少到 ≤ 6 时退化回链表


:::tip
#### 什么是红黑树原理？

https://oi-wiki.org/ds/rbtree/

####  红黑树 vs AVL树**

| 特性 | 红黑树 | AVL树 |
|------|--------|-------|
| 平衡程度 | 相对平衡（最长≤2×最短） | 严格平衡（高度差≤1） |
| 插入/删除 | 最多3次旋转 | 可能需要多次旋转 |
| 查询速度 | 稍慢 | 更快 |
| 适用场景 | 插入/删除频繁 | 查询频繁 |

#### 为什么HashMap用红黑树？

1. **查找效率**: O(log n) 比链表的 O(n) 快
2. **插入删除**: 比AVL树更快（旋转次数少）
3. **平衡维护成本低**: 适合频繁增删的场景
4. **最坏情况可控**: 不会退化成链表

#### 红黑树的时间复杂度

- **查找**: O(log n)
- **插入**: O(log n)
- **删除**: O(log n)
- **空间**: O(n)

红黑树通过巧妙的着色规则和旋转操作，在保持相对平衡的同时，将调整成本控制在可接受范围内，是一种工程上非常实用的数据结构！
:::

### 3.2 实现原理

#### 存储过程（put方法）

```java
public V put(K key, V value) {
    if (key == null)
        return putForNullKey(value); // null键总是存在table[0]
    
    int hash = hash(key.hashCode());
    int i = indexFor(hash, table.length);
    
    // 遍历链表，查找是否存在相同key
    for (Entry<K,V> e = table[i]; e != null; e = e.next) {
        Object k;
        if (e.hash == hash && ((k = e.key) == key || key.equals(k))) {
            V oldValue = e.value;
            e.value = value; // 替换旧值
            return oldValue;
        }
    }
    
    // 添加新元素
    modCount++;
    addEntry(hash, key, value, i);
    return null;
}
```

**关键步骤**：
1. 计算key的hash值
2. 通过hash值计算数组索引
3. 检查该位置是否已有元素
4. 如果存在相同key，替换value
5. 否则在链表头部插入新元素
6. 检查是否需要扩容

#### 获取过程（get方法）

```java
public V get(Object key) {
    if (key == null)
        return getForNullKey();
    
    int hash = hash(key.hashCode());
    
    // 遍历链表查找
    for (Entry<K,V> e = table[indexFor(hash, table.length)];
         e != null;
         e = e.next) {
        Object k;
        if (e.hash == hash && ((k = e.key) == key || key.equals(k)))
            return e.value;
    }
    return null;
}
```

### 3.3 哈希冲突解决

**当两个key的hashCode相同时**：
1. HashMap使用**链地址法**解决冲突
2. 相同hash值的元素通过链表连接
3. 查找时遍历链表，使用`equals()`方法比较key
4. JDK 1.8中，链表过长时转为红黑树提高查询效率

**其他解决方案**：
- 开放定址法（线性探测、二次探测、伪随机探测）
- 再哈希法
- 链地址法（HashMap采用）
- 建立公共溢出区

### 3.4 扩容机制（rehash）

```java
void resize(int newCapacity) {
    Entry[] oldTable = table;
    int oldCapacity = oldTable.length;
    
    if (oldCapacity == MAXIMUM_CAPACITY) {
        threshold = Integer.MAX_VALUE;
        return;
    }
    
    Entry[] newTable = new Entry[newCapacity];
    transfer(newTable); // 重新计算所有元素位置
    table = newTable;
    threshold = (int)(newCapacity * loadFactor);
}
```

**扩容触发条件**：
- 当前元素数量 >= threshold（容量 × 加载因子）
- 默认初始容量：16
- 默认加载因子：0.75
- 扩容倍数：2倍

**注意**：扩容时需要重新计算所有元素的index，而不是简单移动位置

### 3.5 关键参数

```java
static final int DEFAULT_INITIAL_CAPACITY = 16;  // 默认初始容量
static final int MAXIMUM_CAPACITY = 1 << 30;     // 最大容量
static final float DEFAULT_LOAD_FACTOR = 0.75f;  // 默认加载因子
transient Entry[] table;                         // 存储数组
```

**初始容量规则**：
- 实际容量 >= 指定容量的最小2的幂次方
- 例如：指定容量为10，实际容量为16

### 3.6 时间复杂度

* **均摊、典型**：O(1)
* **最差情况（冲突极端坏）：O(n)**
  * JDK1.7：链表结构
  * JDK1.8：链表长度未达到树化阈值时仍是 O(n)
* **桶树化后的最差情况**：O(log n)
  * JDK1.8 引入红黑树优化，当链表超过阈值并且容量满足条件 → O(log n)


## 四、HashMap vs Hashtable

| 特性 | HashMap | Hashtable |
|------|---------|-----------|
| 线程安全 | 非线程安全 | 线程安全（synchronized） |
| null值 | Key和Value均可为null | 均不允许null |
| 性能 | 更高 | 较低 |
| 初始容量 | 16 | 11 |
| 扩容方式 | capacity × 2 | capacity × 2 + 1 |
| 推荐使用 | 单线程环境 | 不推荐（遗留类） |
| 替代方案 | - | ConcurrentHashMap |
| 继承关系 | 实现Map接口 | 实现Map接口和Dictionary抽象类 |

**hash计算差异**：
- **Hashtable**：`(hash & 0x7FFFFFFF) % tab.length`
- **HashMap**：二次hash后取模，散列更均匀

## 五、HashSet实现原理

HashSet基于HashMap实现：
- 底层使用HashMap存储数据
- 元素作为HashMap的key
- 所有value都是同一个静态Object对象

```java
private transient HashMap<E,Object> map;
private static final Object PRESENT = new Object();

public boolean add(E e) {
    return map.put(e, PRESENT) == null;
}
```

**保证不重复的机制**：
1. 先比较hashCode
2. 如果hashCode相同，再用equals()比较
3. 两者都相同才认为是重复元素

## 六、ArrayList vs LinkedList

| 特性 | ArrayList | LinkedList |
|------|-----------|------------|
| 数据结构 | 动态数组 | 双向链表 |
| 随机访问 | O(1) - 快速 | O(n) - 需要遍历 |
| 插入/删除（中间） | O(n) - 需要移动元素 | O(1) - 只需修改指针 |
| 插入/删除（首尾） | O(1) 或 O(n) | O(1) |
| 内存占用 | 连续内存 | 分散内存，额外指针开销 |
| 扩容机制 | 需要 | 不需要 |
| 适用场景 | 频繁随机访问 | 频繁插入删除 |

**ArrayList扩容机制**（JDK 1.8+）：
- 初始容量：0（延迟初始化）
- 首次add时初始化为10
- 扩容增量：当前容量的50%, 会扩容为 1.5 倍
  - `int newCapacity = oldCapacity + (oldCapacity >> 1);  // 1.5倍`

## 七、ArrayList vs Vector

| 特性 | ArrayList | Vector |
|------|-----------|--------|
| 线程安全 | 否 | 是（synchronized） |
| 性能 | 较高 | 较低 |
| 扩容增量 | 50% | 100% |
| 推荐使用 | 是 | 否（遗留类） |

## 十、Queue操作

### 10.1 poll() vs remove()

```java
Queue<String> queue = new LinkedList<>();
queue.offer("string");

System.out.println(queue.poll());   // 返回并删除，空队列返回null
System.out.println(queue.remove()); // 返回并删除，空队列抛NoSuchElementException
```

| 方法 | 队列为空时行为 |
|------|---------------|
| poll() | 返回null |
| remove() | 抛出异常 |

## 十一、线程安全集合

### 11.1 JDK原生线程安全类

- **Vector**：线程安全的ArrayList
- **Hashtable**：线程安全的HashMap
- **Stack**：线程安全的栈

### 11.2 并发包（JDK 1.5+）

- **ConcurrentHashMap**：高性能线程安全Map
- **CopyOnWriteArrayList**：读多写少场景
- **ConcurrentLinkedQueue**：非阻塞队列
- **BlockingQueue系列**：阻塞队列

### 11.3 Collections工具类

```java
List<String> list = new ArrayList<>();
List<String> syncList = Collections.synchronizedList(list);
```

**原理**：通过内部类包装，在方法调用时自动加synchronized锁

## 十二、迭代器（Iterator）

### 12.1 基本使用

```java
List<String> list = new ArrayList<>();
Iterator<String> it = list.iterator();

while(it.hasNext()) {
    String obj = it.next();
    System.out.println(obj);
}
```

### 12.2 Iterator vs ListIterator

| 特性 | Iterator | ListIterator |
|------|----------|--------------|
| 适用范围 | Set和List | 仅List |
| 遍历方向 | 单向（向前） | 双向（向前/向后） |
| 额外功能 | 无 | add、set、获取索引等 |
| 继承关系 | 接口 | 继承自Iterator |

### 12.3 安全性特点

Iterator提供**fail-fast机制**：
- 遍历过程中检测集合修改
- 发现并发修改时抛出`ConcurrentModificationException`
- 保证迭代安全性

## 十三、HashMap vs TreeMap

| 场景 | 推荐选择 | 原因 |
|------|---------|------|
| 插入/删除/查找 | HashMap | 时间复杂度O(1)，更快 |
| 有序遍历 | TreeMap | 基于红黑树，Key自然有序 |
| 排序需求 | TreeMap | 支持自定义Comparator |

## 十四、集合不可修改

使用`Collections.unmodifiableCollection()`创建只读集合：

```java
List<String> list = new ArrayList<>();
list.add("x");

Collection<String> clist = Collections.unmodifiableCollection(list);
clist.add("y"); // 抛出UnsupportedOperationException
//它返回的不是一个新的集合，而是一个 “只读代理 Wrapper”，所有修改操作都会被这个 Wrapper 拦截，并直接抛出异常。
```

**应用场景**：
- 保护数据不被意外修改
- 返回内部集合的只读视图
- 常量集合定义

## 十五、最佳实践总结

### 15.1 选择建议

- **频繁查询**：使用ArrayList或HashMap
- **频繁插入删除**：使用LinkedList
- **需要排序**：使用TreeMap或TreeSet
- **线程安全**：使用ConcurrentHashMap
- **不允许重复**：使用Set
- **键值对存储**：使用Map

### 15.2 性能优化

1. **预设容量**：避免频繁扩容
2. **选择合适的加载因子**：平衡空间和时间
3. **避免在循环中创建集合**
4. **使用合适的初始容量**
5. **注意null值处理**

### 15.3 注意事项

- HashMap的Key应该重写hashCode()和equals()
- 遍历时不要直接修改集合，使用Iterator.remove()
- 注意线程安全问题
- ArrayList初始化策略已变化（延迟初始化）
- 优先使用接口类型声明变量
