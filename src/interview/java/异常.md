# Java 异常处理完全指南

## 一、异常处理核心概念

### 1.1 throw 和 throws 的区别

在 Java 异常处理中，`throw` 和 `throws` 是两个容易混淆的关键字：

- **throw**：用于在代码中实际抛出一个异常对象。它是一个动作，表示"我现在要抛出这个异常"。
  ```java
  throw new IllegalArgumentException("参数不合法");
  ```

- **throws**：用于方法声明中，表示该方法可能会抛出某种类型的异常。它是一个声明，告诉调用者"这个方法可能会抛出这些异常，请做好处理准备"。
  ```java
  public void readFile() throws IOException {
      // 方法实现
  }
  ```

### 1.2 final、finally、finalize 的区别

这三个关键字虽然拼写相似，但用途完全不同：

**final** - 修饰符关键字
- 修饰类：该类不能被继承，如 `String` 类
- 修饰方法：该方法不能被子类重写（override）
- 修饰变量：该变量成为常量，一旦赋值后不可修改

**finally** - 异常处理关键字
- 是 `try-catch-finally` 结构的最后一部分
- 无论是否发生异常，finally 块中的代码都会执行（除非在 finally 之前调用了 `System.exit()` 方法）
- 常用于释放资源、关闭文件流、释放数据库连接或释放锁等清理工作

**finalize** - 对象方法
- 是 `Object` 类的一个方法，在垃圾收集器回收对象时会调用
- 该机制现已不推荐使用，Java 9 中已被标记为过时（deprecated）

## 二、try-catch-finally 使用规则

### 2.1 语法结构的灵活性

try-catch-finally 结构中，**catch 和 finally 都可以省略，但不能同时省略**。也就是说：

- ✅ `try-catch` 结构（省略 finally）
- ✅ `try-finally` 结构（省略 catch）
- ❌ 不能只有 `try` 块

### 2.2 finally 的执行时机

**finally 块一定会执行**，即使 catch 块中有 return 语句。执行顺序如下：

1. 执行 try 块代码
2. 如果发生异常，执行 catch 块代码
3. 如果 catch 块中有 return 语句，会先保存返回值
4. 执行 finally 块代码
5. 返回之前保存的返回值

> **特殊情况：以下 4 种情况下 finally 块不会被执行**
> 
> 1. 在 finally 语句块中发生了异常
> 2. 在前面的代码中调用了 `System.exit()` 退出程序
> 3. 程序所在的线程死亡
> 4. 关闭 CPU（系统崩溃）

在 Java 中，所有异常都有一个共同的祖先：`java.lang` 包中的 **Throwable** 类。

### 3.2 Error（错误）

**Error** 是程序无法处理的错误，表示运行应用程序中的严重问题：

- 大多数错误与代码编写者的操作无关，而是 JVM（Java 虚拟机）运行时出现的问题
- 典型示例：
  - `VirtualMachineError`（虚拟机运行错误）
  - `OutOfMemoryError`（内存溢出错误）
  - `NoClassDefFoundError`（类定义错误）
- 这些错误是**不可查的**（Unchecked），因为它们超出了应用程序的控制和处理能力
- 对于设计合理的应用程序，即使发生了错误，本质上也不应该试图去处理它

### 3.3 Exception（异常）

**Exception** 是程序本身可以处理的异常，它有一个重要的子类：**RuntimeException**。

**RuntimeException（运行时异常）**
- 由 Java 虚拟机抛出，属于**不可查异常**（Unchecked Exception）
- 常见的运行时异常：
  - `NullPointerException`：空指针异常，访问的变量没有引用任何对象
  - `ArithmeticException`：算术运算异常，如整数除以 0
  - `ArrayIndexOutOfBoundsException`：数组下标越界异常

**其他 Exception**
- 属于**可查异常**（Checked Exception），必须在代码中显式处理
- 编译器会强制要求捕获或声明这些异常

### 3.4 异常和错误的核心区别

- **异常（Exception）**：程序可以处理，应该被捕获和处理
- **错误（Error）**：程序无法处理，通常导致程序终止

## 四、常见异常类型

### 4.1 常见异常清单

- **NullPointerException**：空指针异常
- **ClassNotFoundException**：指定类不存在
- **NumberFormatException**：字符串转换为数字异常
- **IndexOutOfBoundsException**：数组下标越界异常
- **ClassCastException**：数据类型转换异常
- **FileNotFoundException**：文件未找到异常
- **NoSuchMethodException**：方法不存在异常
- **IOException**：IO 异常
- **SocketException**：Socket 异常

## 五、Throwable 类常用方法

Throwable 类提供了以下常用方法来获取异常信息：

- **`public String getMessage()`**：返回异常发生时的详细信息
- **`public String toString()`**：返回异常发生时的简要描述
- **`public String getLocalizedMessage()`**：返回异常对象的本地化信息。子类可以覆盖这个方法生成本地化信息，如果子类没有覆盖该方法，则返回的信息与 `getMessage()` 相同
- **`public void printStackTrace()`**：在控制台上打印 Throwable 对象封装的异常信息，包括异常类型、异常消息和堆栈跟踪

## 六、异常处理最佳实践

### 6.1 基本原则

- **try 块**：用于捕获可能发生异常的代码。其后可接零个或多个 catch 块，如果没有 catch 块，则必须跟一个 finally 块
- **catch 块**：用于处理 try 捕获到的异常，可以有多个 catch 块处理不同类型的异常
- **finally 块**：用于执行清理工作，无论是否发生异常都会执行

### 6.2 推荐做法

1. 不要捕获过于宽泛的异常类型
2. 在 finally 块中释放资源
3. 优先使用 try-with-resources 语句（Java 7+）自动管理资源
4. 记录异常信息，便于问题追踪
5. 不要忽略异常，至少要记录日志
6. 抛出具体的异常类型，而不是通用的 Exception
